# ChromaStyle 2.0 — палитра фото и гармоничные сочетания

🌐 **Работающий сайт: https://llayon.github.io/alisapalette/**

Локальный инструмент разбора цветовой палитры фотографии и подбора сочетаний.
Всё считается в браузере: без сервера, регистрации, платных API и нейросетей.
Цветовой движок — перцепционные пространства **OKLab / OKLCH**
(евклидово расстояние в OKLab; это **не** CIEDE2000).

Исходный прототип сохранён как `code_artifact.html` (только для истории).

## Локальный запуск

```bash
npm install
npm run dev      # разработка: http://localhost:5173
npm run build    # статическая сборка в dist/
npm run preview  # просмотр сборки: http://localhost:4173
```

## Тесты

```bash
npm test         # Vitest: 50 unit-тестов (цветовая наука, палитра, гармонии, выборка)
npx playwright test   # E2E: 360×800, 390×844, 430×932, 1280×800
```

Скриншоты до/после: `screenshots/` (`node scripts/screenshots.mjs`).

## Story Studio

Открытки 1080×1920 (PNG, 9:16) из собственной фотографии: 4 шаблона
(Editorial, Polaroid, Magazine, Aroma), предпросмотр тем же движком
(`src/story/renderer.js`), кадрирование перетаскиванием, 3–6 оттенков,
названия/HEX/проценты, подпись канала (только валидный @handle, по
умолчанию отсутствует), деликатный брендинг + URL приложения.

- **Сохранить PNG** — всегда доступно, локальный download (имя
  `chromastyle-<шаблон>-1080x1920-<дата>.png`).
- **Поделиться** — Web Share API с заранее подготовленным Blob (кэш с
  версионированием; устаревшая открытка не отправится). Отмена — не ошибка,
  fallback-скачивание при отмене не запускается.
- **Telegram**: `shareToStory` принимает только публичный HTTPS-URL, а
  `shareMessage` требует bot backend — поэтому прямой публикации локального
  PNG нет (без сервера это невозможно без загрузки снимков; мы их не
  загружаем). Сценарий: сохранить PNG → добавить в Stories вручную +
  копирование ссылки на приложение.
- QR-код отложен (требует проверенного локального энкодера; не включаем
  непроверенный код в дизайн).

## Деплой на GitHub Pages

Автоматический: push в `main` запускает `.github/workflows/deploy.yml`
(`npm ci` → `npm test` → `npm run build` → публикация `dist/`).
Источник Pages — **GitHub Actions** (build_type `workflow`).

Статус публикации: вкладка **Actions** репозитория
(`gh run list`, `gh run watch RUN_ID --exit-status`).

В `vite.config.js` стоит `base: './'` — пути относительные, подпапка
репозитория (`/alisapalette/`) поддерживается.

## Архитектура (`src/`)

- `color-science.js` — sRGB↔linear↔OKLab↔OKLCH, gamut mapping (уменьшение chroma
  с сохранением hue/lightness), относительная яркость sRGB, нейтрали.
- `sampling.js` — стратифицированная детерминированная выборка (~7500–9000 точек).
- `palette.js` — детерминированный K-Means в OKLab (+ Median Cut и гистограмма
  в расширенных настройках), медоиды-репрезентанты, спасение акцентов,
  доли ровно 100,0% (наибольшие остатки), роли основной/второстепенный/акцент.
- `harmony.js` — трио «Спокойно / Контрастно / Акцент», 6 классических гармоний,
  отдельная стратегия для нейтралей, разделение «сочетания из фото»
  (только найденное) и «что можно добавить» (сгенерированное).
- `poetic.js` — словарь `POETIC_COLORS` (сохранён), ближайший подбор по OKLab
  со штрафом хроматичности для нейтралей.
- `perfume.js` — парфюмерный движок и каталог из прототипа (не переписан;
  расстояние заменено на OKLab).
- `state.js`, `ui.js`, `main.js` — состояние (активный цвет по id),
  рендер, загрузка фото, пипетка 1×1/3×3/5×5, пины, экспорт Stories 9:16.

## Известные ограничения

- Эмуляция iPhone — только viewport в Chromium; проверка на реальном
  iPhone/Android-устройстве не проводилась.
- Точность палитры зависит от качества фото; сильные JPEG-артефакты и
  пересветы могут давать краевые blend-оттенки малой доли (честно показаны).
- Рекомендации гармоний — эвристики композиции, а не научная оценка красоты.
