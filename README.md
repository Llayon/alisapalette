# ChromaStyle 2.0 — палитра фото и гармоничные сочетания

🌐 **Работающий сайт: https://llayon.github.io/alisapalette/**

Библиотека «Мои палитры», автосохранение, восстановление и перенос проектов
опубликованы 10 ноября 2026 через [PR #6](https://github.com/Llayon/alisapalette/pull/6).
[Проверки и публикация](https://github.com/Llayon/alisapalette/actions/runs/42793432554)
успешны: 134 unit-теста и 320 E2E. На сайте проверен полный цикл сохранения,
перезагрузки, экспорта и импорта с совпадающим PNG. Статус плана:
[PROJECTS_PLAN.md](PROJECTS_PLAN.md).

Локальный инструмент разбора цветовой палитры фотографии и подбора сочетаний.
Сценарий: фото → палитра → сочетания → открытка. Всё считается в браузере:
без сервера, регистрации, платных API и нейросетей.
Цветовой движок — перцепционные пространства **OKLab / OKLCH**
(евклидово расстояние в OKLab; это **не** CIEDE2000).

Исходный прототип сохранён как `code_artifact.html` (только для истории).

## Сохранение работы и проекты

Фото, готовая палитра с ручными правками, выбранный
цвет, настройки анализа и рекомендаций, а также оформление и кадрирование
открытки сохраняются автоматически в IndexedDB. При следующем открытии
восстанавливается последняя работа. Изменения записываются после короткой
паузы; незавершённое перетаскивание не сохраняется.

Статус над основным экраном показывает результат записи. При отказе можно
повторить сохранение; при конфликте вкладок — открыть сохранённую версию или
сохранить свою работу копией. «Открыть сохранённую версию» заменяет локальные
правки данными из хранилища. Данные остаются в этом браузере на этом устройстве.
Очистка данных сайта удаляет их.

Перед сменой фотографии приложение дожидается записи текущей работы. Если
сохранение не удалось, смену можно отменить, скачать проект или явно продолжить
без последних изменений. Старые настройки Story Studio из localStorage
подхватываются при первом запуске; неверные значения игнорируются.

### Мои палитры

«Сохранить в мои палитры» добавляет текущую работу в библиотеку с названием.
Дальнейшие правки сохраняются в той же записи автоматически. Черновики без
явного сохранения в библиотеке не отображаются, но последняя работа
восстанавливается после перезагрузки.

Библиотека показывает превью, цвета и дату изменения; новые изменения поднимают
проект в начало списка. Можно открыть, переименовать, создать отдельную копию
или удалить проект с подтверждением. Перед переключением ожидающая запись
завершается; при ошибке записи переключение останавливается. Удалённая запись
не возвращается из-за устаревшего автосохранения другой вкладки.

Миниатюры хранятся вместе с метаданными: открытие списка не читает все полные
изображения. Диалоги поддерживают Tab, Escape и возврат фокуса; имена выводятся
как текст.

### Резервная копия и перенос

- «Скачать проект» над основным экраном сохраняет текущую работу, включая
  последние правки. Это действие доступно и при отказе автосохранения.
- «Скачать проект» в карточке библиотеки сохраняет выбранный проект.
- «Импортировать проект» в библиотеке принимает `.chromastyle.json` и добавляет
  новую запись. Текущая работа остаётся открытой; импортированную можно открыть
  из библиотеки. Повторный импорт создаёт ещё одну независимую запись.

В файле находятся рабочая фотография PNG, палитра с ручными точками, настройки
анализа, рекомендаций, оформления и кадрирования. При импорте назначаются новые
идентификатор проекта, даты и ревизия. Идентификаторы цветов сохраняются.
Файл можно перенести в другой браузер или на другое устройство.

Ограничения: файл до 24 МиБ, PNG до 16 МиБ, ширина и высота до 1400 px.
Версии, структура, числовые диапазоны и заголовок PNG проверяются до декодирования;
изображение декодируется до записи в базу. Повреждённый файл или отказ записи
не заменяет текущую работу и не оставляет частично импортированный проект.

Формат JSON: `format: "chromastyle-project"`, `formatVersion: 1`,
`project` (схема `schemaVersion: 1`) и `image`
(`type: "image/png"`, `encoding: "base64"`, `data`). Кэши, временные URL и
состояние незавершённых жестов в файл не включаются.

Слой проектов: `src/projects/schema.js` проверяет формат, `storage.js` выполняет
атомарные записи с проверкой ревизии, `snapshot.js` готовит снимок/изображение,
`controller.js` связывает сохранение с контроллерами, `view.js` отображает библиотеку.
`transfer.js` читает и создаёт переносимые файлы проектов без обращения к серверу.
При восстановлении выборка
пикселей создаётся заново, готовая палитра не кластеризуется повторно.

Набор проверок: **134 unit-теста и 320 E2E**; production-сборка выполняется перед
браузерными тестами. Результат конкретного коммита доступен в
[GitHub Actions](https://github.com/Llayon/alisapalette/actions/workflows/deploy.yml).
Проекты проверяются в Chromium на четырёх размерах экрана, Firefox и WebKit:
перезагрузка, сохранение ручных правок и оформления, отказ записи, конфликты вкладок,
операции библиотеки, включая доступность и удаление без восстановления устаревшей записью,
а также резервные копии и перенос файлов между браузерными движками.

## Локальный запуск

```bash
npm ci --no-audit --fund=false  # установка версий из package-lock.json
npm run dev      # разработка: http://localhost:5173
npm run build    # статическая сборка в dist/
npm run preview  # просмотр сборки: http://localhost:4173
```

## Тесты

```bash
npm test         # Vitest: цветовая наука, палитра, гармонии, загрузка, открытки
npx playwright test   # E2E: 360×800, 390×844, 430×932, 1280×800
npm run check    # unit → production-сборка → E2E
```

Скриншоты до/после: `screenshots/` (`node scripts/screenshots.mjs`).

Для первого запуска E2E установите Chromium, Firefox и WebKit: `npm run e2e:install`.
Браузерные проверки работают с production-сборкой; перед отдельным запуском
`npm run e2e` выполните `npm run build`. При падении сохраняются скриншоты и
трассировки в `test-results/`.

Основной набор работает в Chromium на четырёх размерах экрана. Проекты
`firefox-smoke` и `webkit-smoke` проверяют загрузку настоящего PNG, палитру,
сохранение открытки 1080×1920 и возврат фокуса после закрытия студии.
Их можно запустить отдельно:

```bash
npm run e2e -- --project=firefox-smoke --project=webkit-smoke
```

Проверка версии из [PR #5](https://github.com/Llayon/alisapalette/pull/5)
на 9 ноября 2026: **94 unit-теста, production-сборка и 194 E2E прошли**
локально на Windows и в [GitHub Actions на Linux](https://github.com/Llayon/alisapalette/actions/runs/42628915320).
В матрицу экспорта входят 288 комбинаций шаблонов, числа цветов, подписей и
заголовков на каждом из четырёх размеров экрана.

Шрифты Cormorant Garamond, Inter и JetBrains Mono поставляются локально в
`public/fonts/`: WOFF2, кириллица и латиница, используемые начертания, лицензии
SIL OFL и сведения об источниках. Приложение не обращается к Google Fonts.
При отказе шрифтов PNG создаётся с системными заменами; если шрифты загрузятся
позже, открытая студия обновит предпросмотр и PNG. E2E отдельно проверяют
локальную загрузку, отказ и задержку шрифтов.

## Story Studio

Открытки 1080×1920 (PNG, 9:16) из собственной фотографии: 4 шаблона
(Editorial, Polaroid, Magazine, Aroma), предпросмотр тем же движком
(`src/story/renderer.js`), кадрирование перетаскиванием, 3–6 оттенков,
названия/HEX/проценты, подпись канала (только валидный @handle, по
умолчанию отсутствует), деликатный брендинг + URL приложения.

- **Сохранить PNG** — всегда доступно, локальный download (имя
  `chromastyle-<шаблон>-<размер>-<дата>.png`). Основной размер — 1080×1920;
  при отказе большого canvas выполняется повтор 720×1280, фактический размер
  указан в имени файла и статусе студии.
- **Поделиться** — Web Share API с заранее подготовленным Blob (кэш с
  версионированием; устаревшая открытка не отправится). Отмена — не ошибка,
  fallback-скачивание при отмене не запускается.
- **Telegram**: `shareToStory` принимает только публичный HTTPS-URL, а
  `shareMessage` требует bot backend — поэтому прямой публикации локального
  PNG нет (без сервера это невозможно без загрузки снимков; мы их не
  загружаем). Сценарий: сохранить PNG → добавить в Stories вручную +
  копирование ссылки на приложение.
- QR-код отложен (требует проверенного локального энкодера; не включаем
  непроверенный код в дизайн).

Кадрирование в режиме «Заполнить» доступно также с клавиатуры: стрелки
сдвигают фото, Shift увеличивает шаг, Home возвращает исходное положение.
Escape во время перетаскивания отменяет изменение; повторный Escape закрывает
студию и возвращает фокус на кнопку открытия. При смене фотографии crop и
кэш PNG сбрасываются, устаревшие загрузки и результаты экспорта отбрасываются.

## Деплой на GitHub Pages

Автоматический: push в `main` запускает `.github/workflows/deploy.yml`
(`npm ci --no-audit --fund=false` → `npm test` → `npm run build` → установка браузеров → E2E → публикация `dist/`).
Pull request в `main` запускает те же проверки. Публикация разрешена только
из `main` после успешного выполнения всех проверок. При ошибке браузерные
артефакты загружаются в Actions на семь дней.
Источник Pages — **GitHub Actions** (build_type `workflow`).

Статус публикации: вкладка **Actions** репозитория
(`gh run list`, `gh run watch RUN_ID --exit-status`).

Порядок выпуска: создать PR в `main`, дождаться успешного `build`, затем
слить PR. Push, созданный слиянием, сам запускает проверки и публикацию Pages;
отдельный ручной запуск workflow для этого не нужен. В PR задача `deploy`
пропускается. После публикации проверяются загрузка фото и сохранение PNG
на действующем сайте. Отдельный npm audit при установке не запускается.

В `vite.config.js` стоит `base: './'` — пути относительные, подпапка
репозитория (`/alisapalette/`) поддерживается.

## Архитектура (`src/`)

- `color-science.js` — sRGB↔linear↔OKLab↔OKLCH, gamut mapping (уменьшение chroma
  с сохранением hue/lightness), относительная яркость sRGB, нейтрали.
- `sampling.js` — стратифицированная детерминированная выборка (~7500–9000 точек).
- `palette.js` — детерминированный K-Means в OKLab (+ Median Cut и гистограмма
  в расширенных настройках), медоиды-репрезентанты, спасение акцентов,
  доли ровно 100,0% (наибольшие остатки), роли основной/второстепенный/акцент.
- `harmony.js` — трио «Спокойно / Контрастно / Акцент», 6 классических гармоний,
  отдельная стратегия для нейтралей, разделение «сочетания из фото»
  (только найденное) и «что можно добавить» (сгенерированное).
- `poetic.js` — словарь `POETIC_COLORS` (сохранён), ближайший подбор по OKLab
  со штрафом хроматичности для нейтралей.
- `perfume.js` — парфюмерный движок и каталог из прототипа (не переписан;
  расстояние заменено на OKLab).
- `state.js`, `ui.js` — состояние (активный цвет по id) и отображение.
- `main.js` — инициализация и связывание контроллеров.
- `photo-controller.js`, `photo-loader.js`, `demo-scenes.js` — подготовка и
  применение фото, отбрасывание устаревших загрузок, процедурные примеры.
- `palette-controller.js` — пипетка 1×1/3×3/5×5, пины, ручные правки,
  сортировка и обновление затронутых блоков.
- `story/controller.js`, `story/crop-controller.js` — студия, фокус,
  кадрирование, подготовка и версионирование PNG, системная отправка.
- `notifications.js`, `feedback.js` — уведомления, копирование и тактильный отклик.
- `recommendations-controller.js` — настройки рекомендаций; таймер погоды
  независим от пересчёта палитры.

Для локального измерения выбора цвета, движения точки и кадрирования:

```bash
npm run build
node scripts/measure-interactions.mjs
```

Скрипт сам запускает и останавливает preview на порту 4175, сохраняет JSON
в `.verification/performance.json`. Он измеряет обработчик и время до
следующего animation frame в Chromium при 390×844, на обычном CPU и с
четырёхкратным замедлением; перед замером область взаимодействия прокручивается
на экран. Третьим аргументом можно передать каталог другой сборки с `dist/`
для сопоставимого замера. Эти замеры не заменяют проверку реального телефона.
Зафиксированные результаты до/после и ограничения методики:
[`reference/interaction-performance.json`](reference/interaction-performance.json).

Диагностические функции проверки пикселей и монтажа открыток находятся в
`scripts/story-diagnostics.js`. E2E и скрипты отчётов устанавливают их перед
навигацией; в пользовательскую сборку они не включаются. Smoke-проверки
Firefox/WebKit работают без их установки.

## Известные ограничения

- Эмуляция iPhone — только viewport в Chromium; проверка на реальном
  iPhone/Android-устройстве не проводилась.
- Точность палитры зависит от качества фото; сильные JPEG-артефакты и
  пересветы могут давать краевые blend-оттенки малой доли (честно показаны).
- Рекомендации гармоний — эвристики композиции, а не научная оценка красоты.
